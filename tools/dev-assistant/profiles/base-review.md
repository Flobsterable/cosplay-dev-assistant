# Базовые правила ревью агента

## B-CORRECTNESS — корректность и приоритет

Поддерживаемый стек — Kotlin Multiplatform для Android и Desktop JVM: Compose Multiplatform,
Material 3, Ktor, kotlinx.serialization, kotlinx.datetime, Gradle Kotlin DSL.
Точные версии и платформы бери из gradle/libs.versions.toml, settings.gradle.kts
и build.gradle.kts выбранного Git-снимка. Не требуй API из более новой версии.
Конкретные продуктовые контракты и границы модулей задаются правилами самого проекта.

Сначала проверь регрессии и реальные баги, затем архитектурные последствия,
затем конкретные улучшения. Найденное должно быть введено или усугублено PR.
Старую проблему можно упомянуть только как контекст новой регрессии.
Вопросы стиля, субъективные переименования и общие пожелания не являются багами.
Не требуй ViewModel, DI-фреймворк, Navigation или SQL-базу ради самого паттерна.

## B-COROUTINES — Kotlin и корутины

- Nullability, безопасные преобразования DTO, граничные значения, пустые коллекции.
- Structured concurrency и жизненный цикл scope; отсутствие GlobalScope для UI-задач.
- CancellationException должна распространяться; catch(Exception), runCatching
  и retry вокруг suspend-вызовов не должны превращать отмену в успех/резервные данные.
- Отсутствие блокирующих сетевых/файловых операций на UI-потоке.
- Гонки, устаревшие результаты после смены фильтра/маршрута, конкурентный доступ к кэшу.
- Целесообразность преобразований, сортировок и выделения памяти на горячем пути.

## B-COMPOSE — Compose и Material 3

- Побочные эффекты и сетевые запросы не запускаются непосредственно из тела composable.
- Ключи LaunchedEffect/produceState/remember соответствуют зависимостям;
  отмена и перезапуск не оставляют устаревшее состояние.
- DisposableEffect освобождает ресурсы; callback в долгоживущем эффекте не устаревает.
- Состояние поднимается к владельцу; Screen получает данные/события, Route оркестрирует загрузку.
- Loading/Error/Success/Empty, повторная загрузка, сохранение фильтров и возврат работают согласованно.
- LazyColumn keys, дорогие вычисления при recomposition — замечания только с обоснованным сценарием.
- Контраст/темы MaterialTheme, описание значимых иконок, доступность интерактивных элементов.

## B-NETWORK — Ktor, API и данные

- Владение и закрытие HttpClient, корректные Android/Desktop engine, timeouts.
- Обработка HTTP-ошибок и ошибок сериализации соответствует установленной версии Ktor.
- Пустой/неполный ответ, nullable поля, неизвестные значения enum и HTML/JSON-LD fallback.
- Резервный демонстрационный каталог не выдаётся за актуальные серверные данные.
- URL/параметры корректно кодируются; логи не раскрывают токены и персональные данные.
- Даты/часовые пояса и границы фильтров проверяются по фактическим моделям проекта.

## B-PLATFORMS — KMP, модули и платформы

- commonMain не зависит от Android-only API; expect/actual согласованы для обеих платформ.
- feature не связывается напрямую с конкретной реализацией data без обоснования;
  нет циклов зависимостей и недоступного internal API между модулями.
- Изменённые публичные модели/контракты согласованы с вызывающим кодом, сериализацией и docs.
- Android permissions, FileProvider/URI, установка APK и Desktop fallback сохраняют корректность.
- Gradle, JVM/SDK и release workflow не ломают существующие targets и подпись релиза.

## B-TESTS — тесты и формат результата

Предлагай проверку воспроизводимого риска: сценарий/вход → ожидаемое поведение.
Не утверждай, что тесты или сборки запущены: этот анализатор читает код статически.
Каждое замечание должно иметь изменённую строку, риск, условие возникновения,
конкретное исправление и ссылки на прочитанные источники. Не выдумывай баги,
если контекста недостаточно: явно укажи неполноту проверки.
