# Экономный режим агента

По умолчанию /sync и PR review используют LLM_EXECUTION_MODE=economy.
Субагенты разделяют роли и повторно используют локально прочитанные источники.
Разделение ролей не означает повторную отправку всего проекта каждому субагенту.

## Ревью

context_agent локально выбирает изменённые участки и связанные определения BM25-поиском.
code_reviewer одним запросом проверяет базовые и действующие проектные правила.
При наличии замечаний review_verifier получает только замечания, цитируемые источники,
нужные правила и соответствующие части diff. Проверяющий может подтвердить номера
черновиков, но не добавляет новые проблемы. При пустом черновике этого запроса нет.
Полный аудит документации отложен до /sync после merge, поэтому его повторная оплата
в каждом PR отсутствует. Отчёт честно указывает выбранный контекст, без заявления
о полном покрытии репозитория или выполненных тестах.

## Обновление документации

context_agent читает код локально без вызова модели для выбора каждого read/search.
docs_writer получает порции существующих документов и предлагает короткие old/new замены.
docs_checker независимо проверяет факты и полноту КАЖДОГО документа порции, включая
документы без предложенных изменений. Все файлы распределяются по порциям; целевой
размер 24 000 символов определяет упаковку, а не исключение документов. Большой файл
проверяется отдельно. Незнакомый API можно запросить через readPaths по каталогу;
после трёх дополнительных чтений ошибка останавливает запуск без неподтверждённых правок.

Неподтверждённые правки получают одну попытку исправления внутри своей порции.
После успешной проверки всех порций проверяются ссылки всего предложения,
исходный Git-диапазон и локальные правки, затем разрешается запись README/docs.
Процесс не начинает весь платный конвейер заново после 402 или конфликта push.

## Контроль расходов

LLM_MAX_CALLS=24 ограничивает число новых API-вызовов за одну операцию.
LLM_MAX_INPUT_CHARACTERS=1000000 ограничивает суммарный отправленный текст.
Это предохранители расходов: источники не обрезаются ради прохождения проверки.
При превышении операция явно останавливается. Ограничения не являются лимитом в долларах:
цена зависит от модели, токенизации, выходного текста и тарифа провайдера.

usage в JSON-отчёте и строка llm_usage показывают запросы, входные символы, cacheHits,
promptTokens, completionTokens и cache hit/miss токены, если API их возвращает.
Даже неудавшийся API-вызов входит в бюджет. HTTP 400/401/402 не повторяется.

LLM_CACHE_DIR включает кеш точных успешных запросов, например каталог runner.temp
в GitHub Actions. Ключ запроса включает endpoint, модель, параметры, правила и весь
контекст. Ответ подписан HMAC с API-ключом: подмена файла кеша не превращает его
в доверенное одобрение. Кеш не содержит исходных промптов и ключа, но может содержать
фрагменты документации в ответе; выдавайте к нему тот же доступ, что и к проекту.
Обрыв/неверный JSON не кешируется. Точный повтор использует ответ без оплаты API;
изменённый код, правила, текст или модель требуют нового запроса.

## Проверка без оплаты API

Для /sync доступен --plan: он читает текущие Git-объекты и документацию, печатает
порции, ожидаемые вызовы (без дополнительных чтений/исправлений) и предохранители.
Ключ модели не нужен. Нельзя совмещать --plan и --apply.

    node src/cli.js /sync BASE_SHA --head MERGED_SHA --plan

В регрессионном сценарии с 15 руководствами старый thorough-конвейер сделал 63 вызова
и отправил 875104 символа, economy — 8 вызовов и 263472 символа. Это воспроизводимое
сравнение на подменённой модели, а не измерение стоимости или качества реального API.
После проверки необходимости полного старого конвейера можно явно установить
LLM_EXECUTION_MODE=thorough; он значительно дороже и сохраняет старый поиск/аудит.

## Gemini для небольших задач

Основная модель по-прежнему задаётся LLM_MODEL/LLM_BASE_URL/LLM_API_KEY.
Для Gemini используется отдельный секрет GEMINI_API_KEY. Не вставляйте ключ
в код, PR, issues или сообщения: в GitHub откройте Settings → Secrets and variables
→ Actions → New repository secret и сохраните его как GEMINI_API_KEY.
Локально ключ можно записать в tools/dev-assistant/.env, который не коммитится.

LLM_SMALL_TASK_PROVIDER=gemini явно включает маршрутизацию небольших запросов.
По умолчанию GEMINI_MODEL=gemini-3.5-flash-lite, а GEMINI_BASE_URL —
https://generativelanguage.googleapis.com/v1beta/openai. Оба значения можно заменить
для своего Google API-проекта. Модель и совместимый endpoint проверены по документации:
https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite
https://ai.google.dev/gemini-api/docs/openai

Небольшим считается запрос с сериализованными сообщениями не более 24000 символов
и запрошенным ответом не более 6000 токенов. Это консервативное правило по объёму,
а не оценка сложности ещё одним платным LLM-запросом. Пороги задаются через
LLM_SMALL_TASK_MAX_INPUT_CHARACTERS и LLM_SMALL_TASK_MAX_OUTPUT_TOKENS.
Если дополнительное чтение исходников увеличило запрос выше порога, он идёт
на основную модель, потому что теперь требует большего контекста.

При явном включении Gemini без ключа запуск останавливается до первого API-вызова.
Ошибка Gemini или исчерпанная квота не вызывают скрытый повтор на платной основной
модели. Общие предохранители расходов действуют сразу на оба провайдера; usage.perModel
показывает расход для каждой модели отдельно. Кеш привязан к выбранному endpoint,
модели и соответствующему API-ключу; ключ одного провайдера не уходит другому.
Наличие вашего ключа ещё не подтверждает доступность модели/бесплатную квоту:
проверки выполняются на подменённом API и не расходуют ваш баланс.
