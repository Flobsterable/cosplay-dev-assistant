# День 32: автоматическое ревью PR

## Что проверяется

Профиль `tools/dev-assistant/profiles/cosplay-kmp.md` описывает проверки для фактического
стека cosplay-2: Kotlin Multiplatform, Android/Desktop, Compose/Material 3, Ktor,
корутины, сериализация, даты, Gradle и релизы. Версии берутся из Git-снимка приложения.

Порядок приоритетов: баги и регрессии → архитектурные последствия → полезные рекомендации.
Проверяются состояния UI, эффекты/ключи Compose, отмена корутин, владение HttpClient,
ошибки HTTP/DTO, резервные данные, границы модулей, expect/actual и платформенные интеграции.
Не требуется внедрять ViewModel, DI, Navigation или БД без конкретной необходимости.

Каждое замечание содержит приоритет, изменённую строку, сценарий проявления,
последствие, предлагаемое исправление и ссылки на прочитанные источники.
Категории не заполняются искусственно: если подтверждённых замечаний нет, так и написано.

## Пайплайн

1. GitHub Action срабатывает на opened/synchronize/reopened/ready_for_review PR.
2. Загружается базовая ветка; head PR fetch-ится как Git-объект и не запускается.
3. Анализатор получает список файлов и diff merge-base(base, head)..head.
4. Из Git blobs строится корпус Markdown + Kotlin/Gradle/TOML/properties/XML/workflows.
   Исходники читаются из head, старые версии изменённых файлов — из base.
5. Агент сам выбирает документы, определения, вызывающий код и контракты; доступны
   чтение и BM25-поиск, затем отдельная проверка покрытия каталога.
6. Ревьюер формирует структурированный JSON; второй вызов модели проверяет замечания.
7. Код валидирует пути, источники и привязку к действительно изменённым строкам.
8. Публикуется один обновляемый комментарий бота: баги, архитектура, рекомендации.
   Перед записью проверяется, что head PR ещё тот же. Отчёт сохраняется в артефакт.

Сборка, Gradle и код PR в этом процессе не исполняются. Отдельные compile/test jobs
остаются ответственностью приложения. AI-ревью не выставляет автоматическое approval
и не является гарантией отсутствия багов.

## Установка в cosplay-2

Шаблон: `examples/workflows/ai-review.yml`. Скопируйте в `.github/workflows/ai-review.yml`
приложения и замените `REPLACE_WITH_REVIEW_RUNTIME_SHA` на SHA коммита ассистента,
который содержит review-cli.js. Runtime закреплён по SHA, а не по изменяемой ветке PR.

В Settings → Secrets and variables → Actions репозитория приложения:

- Secret `LLM_API_KEY` — ключ DeepSeek.
- Variable `LLM_MODEL` — необязательно; по умолчанию `deepseek-flash`.
- Variable `LLM_BASE_URL` — необязательно; по умолчанию `https://api.deepseek.com`.

GITHUB_TOKEN выдаётся GitHub автоматически. Workflow использует contents:read
и pull-requests:write для комментария. Fork PR и draft PR пропускаются;
для внешних PR не используется pull_request_target и не выдаются секреты.
При отсутствии API-ключа job завершается понятной ошибкой, а не фиктивным ревью.

## Локальный запуск

Задайте PROJECT_ROOT и настройки модели в tools/dev-assistant/.env. base/head должны
существовать в целевом Git-репозитории. Запуск не меняет код и документацию приложения.

```bash
cd tools/dev-assistant
npm run review -- --base develop --head feature/example --repo Flobsterable/cosplay-2 --output /tmp/pr-review
```

Получите review.md и review.json. Без --publish запросов на запись в GitHub нет.
Для публикации нужны --publish --pr NUMBER и GITHUB_TOKEN с правом комментария.
Не вводите токены в аргументы команды.

## Ограничения

Не более 100 изменённых файлов и 80 000 символов diff. Файлы корпуса ограничены
128 КБ каждый, общий корпус — 1,5 МБ. Секретные/скрытые файлы, local.properties,
симлинки и бинарные файлы исключаются. Пропуски перечислены в JSON; при них
Markdown явно сообщает о неполной проверке. Агентный контекст ограничен 100 000
символов и 8 шагами. Большой diff отклоняется целиком, не анализируется молча частично.
Два чтения head перед комментарием уменьшают риск устаревшего отчёта, но запись API
не транзакционна с обновлением PR; SHA всегда указан в комментарии.

В артефакт попадают замечания и метаданные источников, а не полные тексты исходников
или запросы к модели. Код/документы считаются данными, их инструкции не выполняются.

## Демонстрация и сдача

Для видео покажите PR, запуск AI code review в Actions, артефакт review.md/review.json
и комментарий бота. Добавление коммита в тот же PR должно обновить комментарий.
Не сливайте намеренно внесённую демонстрационную ошибку в develop.
