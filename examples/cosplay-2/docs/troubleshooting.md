# Диагностика приложения

## Отображаются демонстрационные фестивали

При ошибке POST /api/events/filter_list CosplayRepositoryImpl возвращает встроенные
fallbackFestivals и fallbackEventTypes с isFallback=true.
Это фиксированные демонстрационные записи, а не актуальный ответ сервера или дисковый кэш.
Проверьте доступность cosplay2.ru и сообщения AppLogger с тегом CosplayRepo.

## Нет изображения, описания или ссылок

Список, JSON-LD архив и HTML-страница фестиваля загружаются раздельно.
Ошибка JSON-LD сама по себе не прерывает получение списка.
Без изображения схемы используется URL https://cosplay2.ru/files/{id}/logo.png.
Если get_pages/home не загрузилась, детали используют резервное описание и пустой список ссылок.
Ошибка разбора или изменения HTML внешнего сайта могут повлиять на дополнительные данные.

## Пустой список после поиска

Условия фильтрации применяются вместе: актуальность, тип, месяц и текстовый запрос.
Очистите запрос, выберите все типы и все месяцы. «Актуальные» показывают только Future.
Статус Future берётся из timestatus внешнего API, а не вычисляется из дат.
При смене года выполняется новая загрузка; текстовый поиск и тип не отправляются в API.

## Ошибка справочника типов

Если GET /api/events/get_types завершился ошибкой или вернул пустой набор,
репозиторий использует fallbackEventTypes. Основной список фестивалей может остаться сетевым,
с isFallback=false. Наличие резервных типов само по себе не означает fallback всего каталога.

## Не появляется обновление

Проверьте наличие последнего GitHub Release, его tagName и APP_VERSION_NAME сборки.
Баннер сравнивает версию релиза с установленной версией и учитывает pendingUpdate.
Не каждый asset подходит: требуется APK без unsigned в имени.
Для Desktop установка APK не выполняется; открывается ссылка на релиз или asset.

## Android не устанавливает APK

Установка требует подтверждения системного установщика. Для текущего источника может
потребоваться разрешение установки неизвестных приложений.
AndroidManifest.xml содержит INTERNET и REQUEST_INSTALL_PACKAGES.
Состояния RequiresInstallPermission и Failed передаются через AppUpdateInstallState.
Сравните подпись новой APK с установленной сборкой; release workflow требует настроенный keystore.

## Release workflow завершился ошибкой

Тег должен равняться v + APP_VERSION_NAME из gradle.properties.
Для подписания нужны четыре секрета: ANDROID_KEYSTORE_BASE64, ANDROID_KEYSTORE_PASSWORD,
ANDROID_KEY_ALIAS и ANDROID_KEY_PASSWORD. Значения секретов не публикуйте в логах и документации.
Ожидаемый результат assembleRelease — composeApp/build/outputs/apk/release/composeApp-release.apk.
Порядок выпуска описан в development.md.
